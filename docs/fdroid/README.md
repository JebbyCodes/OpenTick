# Releasing OpenTick on F-Droid

What is already prepared in this repository:

| Item | Where |
|---|---|
| Store listing: title, short and full description | `fastlane/metadata/android/en-GB/` |
| Icon (512 × 512) and phone screenshots | `fastlane/metadata/android/en-GB/images/` |
| Per-release changelog (`<versionCode>.txt`, under 500 bytes) | `fastlane/metadata/android/en-GB/changelogs/5000.txt` |
| Build recipe (draft) | `docs/fdroid/com.opentick.app.yml` |
| `versionCode` follows the version automatically (`major*1,000,000 + minor*1,000 + patch`, so 0.5.1 is 5001) | `scripts/android/check-android-version.mjs` |

## Why it should be accepted

* Licence: Unlicense (free). All dependencies are free software (see Settings → About → Licences).
* No Google Play Services, no analytics, no advertising, no tracking. Network access is only to servers the person configures (sync) or embeds they add.
* Permissions are explained in `docs/privacy-policy.md`: notifications, boot completed, exact alarms and a foreground service (for the optional timetable notification).

## Steps

1. Tag the release: `npm run bump -- X.Y.Z`, commit, then `git tag vX.Y.Z && git push origin vX.Y.Z`.
2. Fork `https://gitlab.com/fdroid/fdroiddata`, copy `docs/fdroid/com.opentick.app.yml` to `metadata/com.opentick.app.yml`.
3. Test it: `fdroid build -v -l com.opentick.app` (needs the F-Droid build server image; Node, Rust and the Android SDK/NDK are installed by the recipe).
4. Open a merge request.

## Things to check (not verified from this repository)

* The Android project is generated by `tauri android init`; `scripts/android/android-widgets.mjs` then adds the widgets and the background-service Kotlin files and patches the manifest. The recipe runs both. Check that the generated `output:` path matches what your Tauri version produces.
* F-Droid builds offline from vendored sources: if the build server cannot fetch crates or npm packages, add `rustup`/`cargo vendor` steps (`Cargo.lock` and `package-lock.json` are committed so builds are reproducible).
* F-Droid signs the APK itself; do not include a keystore.
* The Kotlin and Rust background-service code has not been compiled in the environment where this release was prepared. Build an APK and a desktop build once and check the notification, alarm and tray behaviour on a real device before tagging.
